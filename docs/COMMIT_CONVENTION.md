# Piggyback 커밋 컨벤션

## 1. 기본 형식

```text
type: 작업 내용
```

예시:

```text
feat: 상담 입력 화면 추가
fix: 준비물 체크 상태 초기화 오류 수정
docs: PR 템플릿 작성
chore: 프로젝트 문서 폴더 추가
```

## 2. 커밋 타입

| 타입 | 사용 시점 | 예시 |
| --- | --- | --- |
| `feat` | 새로운 기능 추가 | `feat: 지점 추천 화면 추가` |
| `fix` | 버그 수정 | `fix: 사기 경고 화면 이동 오류 수정` |
| `docs` | 문서 작성 또는 수정 | `docs: Git 컨벤션 추가` |
| `refactor` | 기능 변화 없는 구조 개선 | `refactor: 상담 결과 컴포넌트 분리` |
| `style` | 코드 포맷, 공백, UI 스타일 조정 | `style: 홈 화면 버튼 간격 조정` |
| `test` | 테스트 코드 추가 또는 수정 | `test: 업무 분류 서비스 테스트 추가` |
| `chore` | 설정, 의존성, 빌드 등 기타 작업 | `chore: 이슈 템플릿 추가` |

## 3. 작성 규칙

- 제목은 한글로 간결하게 작성합니다.
- `update`, `수정`, `작업중`처럼 내용이 불명확한 메시지는 피합니다.
- 서로 관련 없는 변경을 하나의 커밋에 섞지 않습니다.
- 민감 정보 삭제, 설정 변경, API 응답 구조 변경은 커밋 메시지와 PR 본문에 명확히 적습니다.

## 4. 권장 커밋 단위

- 화면 1개 추가
- API 1개 추가
- 컴포넌트 1개 분리
- 문서 1개 작성
- 버그 1개 수정

너무 큰 기능은 화면, API, 연동, 문서처럼 의미 있는 단위로 나눕니다.
